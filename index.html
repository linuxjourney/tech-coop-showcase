Why Homelab-First Cooperative Infrastructure?

Modern cloud infrastructure traps community organizations in expensive recurring SaaS fees, vendor lock-in, and opaque data governance. The Tech Coop Framework proves that small communities can own, govern, and run their own resilient digital services on affordable local hardware.

Absolute Data Sovereignty

Member files, identities, and credentials never touch commercial third-party cloud servers. Data resides on owned physical NVMe storage with monthly offline air-gapped backups.

POSIX 0700 Isolation Zero SaaS Dependence

Rejecting SaaS Extravagance

Replaces thousands of dollars in annual Google Workspace, Microsoft 365, and Dropbox subscriptions with a single refurbished mini-PC server running open-source standards.

Low Power Usage Zero Ongoing Licensing

Infrastructure Deep Dive

Production Topology & Component Map

Every component on `core-node` serves a distinct, least-privilege role. Below is the network and service routing architecture.

Identity & Access (Samba4 AD DC)

Full Kerberos and LDAP implementation running in Samba Active Directory mode on the `COOP.INTERNAL` realm. Provides enterprise identity management and POSIX ACL mapping without external cloud brokers.

Ports: 53, 88, 389, 445, 636 Delegated `svc-lam` Account

Storage Isolation (POSIX DAC)

Individual member home directories at `/srv/share/{username}` are set to mode `0700` (`drwx------`) strictly owned by individual member UIDs. Cross-member access is rejected at the Linux kernel DAC layer.

Kernel DAC Enforcement Zero Cross-Member Leaks

Bespoke Go/HTMX Microservices

All custom services (`blocky-ui` and `coop-library`) are statically compiled pure Go binaries (`CGO_ENABLED=0`) with vendored vanilla htmx. Self-contained, crash-resilient, and running as non-root systemd daemons.

CommonMark/GFM Engine Astronomical Solar Timer

Hardened Administration Gateway

Apache Guacamole HTML5 gateway proxies browser connections into an isolated Windows RSAT VM with native clipboard forwarding and pinned TLS certificates, enabling full Active Directory GUI management from any machine.

Full RSAT Tooling Pinned TLS Fingerprints

Real-World Engineering Maturity

Security Postmortem: Unauthenticated Share Exposure Remediation

Date: 2026-09-19 • Severity: High (Contained in <15 minutes) • Root Cause: Linux Capability DAC Bypass

During initial staging of the Coop Library viewer, private photos from an individual member's personal share were visible over unauthenticated LAN HTTP. The engineering team executed an immediate, blameless postmortem:

1. Root Cause Identification

To allow the unprivileged daemon user to index operational runbooks, `CAP_DAC_READ_SEARCH` was granted in the systemd unit. Combined with an overbroad `SHARE_ROOT=/srv/share`, this bypassed Linux POSIX `0700` DAC permissions.

2. Rapid Containment

Immediately stripped `SHARE_ROOT` and revoked all Linux capabilities from the systemd unit. Scoped the filesystem read boundary strictly to `/opt/coop-docs`. Restarted the service within minutes.

3. Codebase Hardening

Hardcoded a security refusal in Go rejecting multi-user parent roots (`/srv/share`). Added regression tests in `main_test.go` and codified the rule in `docs/patterns.md` to prevent any unauthenticated daemon from bypassing DAC.
